# Ассемблер УВМ. Вариант №28

## Этап 1. Промежуточное представление

Программа читает команды из JSON-файла и преобразует их в список словарей с полями A, B, C и D.

Поддерживаются четыре команды:

- load: загрузка константы C в регистр B, A=1
- read: чтение значения из памяти, A=5
- write: запись значения в память, A=0
- not: побитовое НЕ, A=15

## Функции

- mask(n): создание битовой маски.
- check_value(): проверка значения поля.
- asm_const(): загрузка константы.
- asm_read(): чтение из памяти.
- asm_write(): запись в память.
- asm_not(): побитовое НЕ.
- asm(): обработка списка команд.
- main(): чтение JSON и запуск программы.

## Запуск

```bash
python -m src.main --input tests/specification.json --output result.bin --test
```

Параметры:
- --input: путь к JSON-файлу
- --output: путь к будущему бинарному файлу
- --test: вывод внутреннего представления

На первом этапе бинарный файл не создаётся.

## Проверка

python -m tests.test_assembler

## Этап 2. Формирование машинного кода

Во втором этапе реализовано преобразование команд из промежуточного представления в машинный код.

Для каждой команды используются поля A, B, C и D, расположенные на определённых битовых позициях. Поля объединяются побитовыми сдвигами и операцией ИЛИ.

Все команды занимают 3 байта. Для записи используется порядок Little-Endian.

Добавлены функции:

- encode_const(): кодирование загрузки константы.
- encode_read(): кодирование чтения из памяти.
- encode_write(): кодирование записи в память.
- encode_not(): кодирование побитового НЕ.
- asm_bytes(): сборка машинного кода программы.

Пример запуска:

python -m src.main --input tests/specification.json --output result.bin --test

После запуска создаётся двоичный файл result.bin.
В тестовом режиме выводятся поля команд, последовательности байтов, количество команд и размер файла.
Все четыре команды проверяются по байтовым последовательностям из спецификации варианта №28.

Запуск тестов:
python -m tests.test_assembler

## Этап 3. Интерпретатор и операции с памятью

Реализован интерпретатор команд УВМ для варианта №28.

Программа читает двоичный файл, преобразует команды во внутреннее представление и последовательно выполняет их.

Используется массив из 32 регистров и общая память на 65536 ячеек. Машинные команды и данные хранятся в одном массиве.

### Поддерживаемые команды

- load: загрузка константы в регистр.
- read: чтение значения из памяти в регистр.
- write: запись значения регистра в память.

Выполнение операции not относится к четвёртому этапу.

### Функции

- decode(): перевод машинной команды в поля A, B, C, D.
- execute(): выполнение машинных команд.
- save_dump(): сохранение диапазона памяти в CSV.
- main(): чтение аргументов и запуск интерпретатора.

### Запуск

Сначала создаётся двоичный файл:

`python -m src.main --input tests/copy_array.json --output copy.bin`

Затем запускается интерпретатор:

`python -m src.interpreter --input copy.bin --output dump.csv --start 200 --end 202`

Параметры:

- --input: путь к двоичному файлу.
- --output: путь к CSV-файлу.
- --start: начальный адрес памяти.
- --end: конечный адрес памяти включительно.

### Тестирование

`python -m tests.test_interpreter`

Тестовая программа записывает массив [10, 20, 30] по адресам 100–102 и копирует его по адресам 200–202.
Проверяется работа команд загрузки, чтения и записи, общая память команд и данных, декодирование инструкций и сохранение CSV-дампа.

## Этап 4. Реализация АЛУ

В интерпретатор добавлено выполнение операции побитового НЕ.

Команда `not` имеет код A=15. Поле B определяет регистр с исходным числом. Поле C определяет регистр, содержащий адрес памяти для записи результата.

Для проверки создан файл `tests/not_test.json`. Программа выполняет операцию над числами 10, 0 и 255.

Результаты сохраняются в памяти по адресам 200–202.

### Запуск

Создание машинного кода:
python -m src.main --input tests/not_test.json --output not.bin --test

Выполнение программы:

python -m src.interpreter --input not.bin --output not_dump.csv --start 200 --end 202

Результаты проверяются по содержимому `not_dump.csv`.
Ожидаемые значения:
- 200: -11
- 201: -1
- 202: -256

## Этап 5. Выполнение тестовой задачи

Реализована поэлементная обработка вектора длины 10 с помощью команды побитового НЕ.

Исходный вектор записывается в общую память УВМ по адресам 200–209. Каждый элемент считывается из памяти, обрабатывается командой not и записывается по исходному адресу.

### Функции

- create_program(): создание программы УВМ для обработки вектора.
- practice(): формирование трёх примеров, компиляция, выполнение и проверка результатов.

### Примеры

Созданы три программы с различными исходными векторами:

1. Числа от 0 до 9.
2. Числа от 10 до 100 с шагом 10.
3. Степени двойки и граничные значения.

Результаты сохраняются в файлы vector_1.csv, vector_2.csv и vector_3.csv.

### Запуск

python -m tests.vector_examples


Программа создаёт три JSON-файла, три двоичных файла и три CSV-дампа.
Для каждого примера проверяются все 10 полученных значений.

### Результат

cat vector_1.csv vector_2.csv vector_3.csv
Все три программы выполняют побитовое НЕ над вектором длины 10 и записывают результаты в исходные ячейки памяти.
